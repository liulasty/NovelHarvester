# oldtimesxs.com 旧时光文学（`scrape-oldtimesxs.js`）

与项目整体流程一致：分章进 `chapters/`，合并进 `merged/`（有 `--merge-title` 时以书名为文件名，否则为 `全文合并.txt`）。

示例目标：`春秋风华录`（`/go/185033/`），实测 484 章。

## 目录页

入口可传书籍总览 `https://www.oldtimesxs.com/go/{bookId}/`，也可直接传某章 `.../go/{bookId}/{chapterId}.html`（脚本按 `/go/{bookId}/` 归一）。

目录由两部分按阅读顺序拼接：

| 来源 | 选择器 | 内容 |
|------|--------|------|
| 总览页 `/go/{bookId}/` | `#list-chapterAll dd a` | 前 100 条（楔子、第1章 …） |
| 分页目录 `/go/{bookId}/{n}/` | `dl.book.chapterlist > div dd a` | 后续章节，`n=1,2,…` |

- **分页目录页头部**另有「最新章」「开始阅读」链接（如「第465章」），它们不在 `dl.book.chapterlist > div` 内，选择器天然排除，避免乱序/重复。
- 每页读取后取 `.page_num` 的「下一页」：当它回落到总览 `/go/{bookId}/` 或本页无新章节时停止翻页。
- 章节链接形如 `/go/{bookId}/{chapterId}.html`（`chapterId` 为站点内部数字 ID，非连续），**以目录 DOM 顺序为准**，脚本按 href 去重。

## 正文与章内分屏

- 正文容器：`#txt`（`<p>` 段落，`innerText`）。
- **章内多屏**：同一章的后续屏为 `{chapterId}_1.html`、`{chapterId}_2.html` …
  - `h1` 形如 `第293章（第1页）` / `第293章（第2页）`。
  - **坑**：不存在的 `_N.html` 不会 404，而是**回落到第 1 屏**（例如第 293 章只有 2 屏，`_2.html` 返回的仍是第 1 屏）。
  - 因此脚本**不盲目自增 `_N`**，而是读取页面「下一章」链接：仅当它仍指向**相同 `chapterId` 且页码更大**时才继续抓下一屏；一旦指向其他章节或页码回退即停止。多屏正文按顺序以空行拼接。
- 未发现图片、加密脚本或 `.wen` 类解码，无需 `timg-map`。

## 状态码说明

站点对部分请求返回 **HTTP 503 但页面内容正常**。脚本不依赖 `response.status()`，以 DOM（目录链接 / `#txt` 非空）作为就绪判断。

## 用法

```bash
node gaode/oldtimesxs/scrape-oldtimesxs.js https://www.oldtimesxs.com/go/185033/ --out-dir=novel-output/oldtimesxs-185033 --merge --merge-title=春秋风华录
```

试跑前 N 章：URL 后加数字，例如 `… /go/185033/ 3`。

## 注意事项

- 已存在的分章文件（>100 字节）默认跳过，需加 `--force`（或 `OLDTIMESXS_FORCE=1`）强制重拉。
- 失败章节写入 `novel-output/<dir>/oldtimesxs_failures.jsonl`（`appendFailureLog`），不中断主流程。
- 有头调试：`OLDTIMESXS_HEADED=1` 或 `NOVEL_HEADLESS=0`。
- 脚本导出 `discoverChapters` / `extractChapterText`，便于单章核对；直接执行时才进入 `main()`。
